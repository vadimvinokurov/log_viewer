1. Общий обзор

Log Viewer — десктопное приложение для просмотра лог-файлов, построенное на PySide6 (Qt6). Архитектура следует MVP-подобному паттерну: ядро (core/) содержит бизнес-логику без зависимостей от Qt, а GUI (gui/) — только представление и координация.

core/ — Модель и логика

Не импортирует Qt. Содержит парсер, хранилище, фильтры, поиск, подсветку, язык запросов, темы и конфигурацию.

gui/ — Представление

Qt-виджеты. app.py (MainWindow) — координатор, связывающий сигналы и управляющий состоянием.

Единственный источник истины — LogStore. Все данные (строки логов, фильтры, подсветка, поиск, пины) живут в нём. GUI читает из него и подписывается на изменения.

Все модели определены в core/models.py (~235 строк).

Ключевые структуры

LogLine

Dataclass: line_number, timestamp (ms), category, level (LogLevel), message, file_offset, line_length.

RowRef

Лёгкий прокси для доступа к строке. Хранит ссылку на LogStore и индекс. Данные извлекаются лениво.

Filter

Поля: pattern (строка), mode (SearchMode). Используется для фильтрации и поиска.

Highlight

Поля: pattern, mode (SearchMode), color (hex). Подсветка совпадений в таблице.

SearchState

Поля: pattern, mode, direction, matches (ndarray), current_index, in_search.

CategoryNode

Поля: name, full_path, enabled, line_count, children. Дерево категорий.

NumPy-типы

OFFSET_DTYPE — структурированный dtype для файловых оффсетов. SPAN_DTYPE — для спанов (offset, length) сообщений. Используются для векторизованных операций.

3. Загрузка файлов

Загрузка происходит в фоновом потоке FileLoaderThread (gui/app.py), чтобы не блокировать GUI.

Пользователь выбирает файл → FileLoaderThread.run() → Чтение в bytes
↓
LogStore.load_bytes(raw) → detect_format_bytes() → scan_line_starts_fast()
↓
parse_batch_fast() → SoA-массивы → _finalize_load()
↓
Дерево категорий + Подсчёт уровней → Начальная фильтрация
↓
Сигнал в GUI → Обновление таблицы

LogStore.load_bytes() — шаги

  1. Сохраняет сырые байты в self._buf (bytearray)
  2. detect_format_bytes() — определяет KSIVA или PLAIN по наличию [LOG_
  3. scan_line_starts_fast() — находит границы строк (Cython-ускоренный поиск \n)
  4. parse_batch_fast() — пакетный парсинг: извлечение timestamp, category, level
  5. Заполняет NumPy-массивы: category_ids (uint16), levels (uint8), line_starts (uint64)
  6. _finalize_load() — дерево категорий, подсчёт уровней, применение фильтров
Производительность: Сырые байты хранятся как единый bytearray. Парсинг использует Cython (~50x быстрее чистого Python). Строки не декодируются до момента отображения — ленивый доступ.

4. Парсинг логов

core/parser.py (~984 строки) — самый объёмный файл в ядре.

Форматы

KSIVA (структурированный)

// Шаблон:
timestamp category [LOG_LEVEL] message

// Пример:
2024-01-01T10:00:00 app/main [LOG_INFO] Starting

Уровень — по префиксу LOG_. Нет уровня → INFO. Нет категории → «uncategorized».

PLAIN (простой текст)

Some random log line
Another line without format

Все строки: уровень INFO, категория «uncategorized».

Определение формата

detect_format_bytes() проверяет первые ~4096 байт на [LOG_. Найдено → KSIVA, иначе → PLAIN.

Уровни парсинга

ФункцияНазначениеРеализация
scan_line_starts_fast()Границы строкCython: поиск \n. Возвращает массив оффсетов.
parse_batch_fast()Полный парсингCython: извлекает timestamp, category, level для всех строк.
parse_minimal_batch()ФоллбэкЧистый Python. Медленнее, работает без Cython.
parse_columns()Одна строкаВызывается при отображении. Извлекает timestamp, category, level, message.

SoA (Structure of Arrays)

# Вместо массива объектов LogLine:
category_ids = np.array([...], dtype=uint16)   # ID категорий
levels       = np.array([...], dtype=uint8)     # Уровни
line_starts  = np.array([...], dtype=uint64)    # Оффсеты в _buf
Почему SoA: NumPy-массивы компактны и поддерживают векторизованные операции. Фильтрация по уровню — одна операция вместо цикла.

5. Хранение — LogStore

core/log_store.py (~475 строк). Центральное хранилище.

class LogStore:
    # Сырые данные
    _buf: bytearray              # Весь файл как байты
    _buf_lower: bytearray        # Кэш lowercase (ленивый)
    _buf_str: str | None         # Кэш строки (для regex)
    n: int                       # Количество строк

    # SoA-массивы
    category_ids: ndarray[uint16]
    levels: ndarray[uint8]
    line_starts: ndarray[uint64]

    # Метаданные
    _format: LogFormat
    _category_names: list[str]
    _category_name_to_id: dict
    category_tree: CategoryNode
    category_counts: dict
    level_counts: dict

    # Результат фильтрации
    filtered_indices: ndarray

    # Подсистемы
    pipeline: FilterPipeline
    search_engine: SearchEngine

Ленивый доступ

МетодВозвращаетКак работает
get_columns(idx)(timestamp, category, level, message)Парсит строку из _buf по оффсету line_starts[idx]
get_message(idx)Текст сообщенияИзвлекает message-часть из буфера
get_raw(idx)Полная строкаБайты между line_starts[idx] и line_starts[idx+1]

Делегирование

LogStore делегирует операции подсистемам:

  • add_filter(), remove_filter() → self.pipeline
  • search(), next_match() → self.search_engine
  • toggle_level(), enable_category() → self.pipeline

_finalize_load()

  1. _build_category_tree() — иерархическое дерево из flat-списка категорий (разделитель /)
  2. _count_levels() — np.bincount(levels), O(n)
  3. pipeline.apply() — начальная фильтрация

6. Конвейер фильтрации — FilterPipeline

core/filter_pipeline.py (~459 строк).

class FilterPipeline:
    filters: list[Filter]            # Фильтры
    filter_enabled: list[bool]       # Включён/выключен
    _filter_masks: list[ndarray]     # Кэш масок

    highlights: list[Highlight]      # Подсветки
    highlight_enabled: list[bool]

    pinned_rules: list[Filter]       # Закреплённые строки
    pinned_enabled: list[bool]
    _pin_masks: list[ndarray]

    disabled_levels: set[int]        # ID отключённых уровней
    disabled_categories: set[int]    # ID отключённых категорий
    _term_cache: dict                # Кэш термов

apply() — основная логика

1. cat_mask = включённые категории по category_ids
2. level_mask = включённые уровни по levels
3. filter_masks = маски каждого фильтра (PLAIN/REGEX/SIMPLE/LINE_NUMBER)
4. combined = cat_mask & level_mask & (f₁ | f₂ | ... ) — фильтры через OR
5. pin_mask = закреплённые строки (обходит все фильтры)
6. result = combined | pin_mask
7. filtered_indices = np.where(result)[0]

compute_mask() — маска одного фильтра

РежимАлгоритм
PLAINПоиск подстроки в _buf_lower. Позиции → строки через np.searchsorted.
REGEXre.finditer() по _buf_str. Позиции → строки.
SIMPLEAST через simple_query.parse_query(). Вычисление eval_masks().
LINE_NUMBERПрямой доступ по номеру строки.
Маппинг позиций на строки: Совпадение на позиции pos → строка = np.searchsorted(line_starts, pos, side='right') - 1. O(log n) на совпадение.

7. Язык запросов — Simple Query

core/simple_query.py (~258 строк). Булев язык с AST.

Синтаксис

"error" "timeout"          # неявный AND
"error" AND "timeout"     # явный AND
"error" OR "warning"      # OR
NOT "info"                 # NOT
("error" OR "warning") AND "network"  # группировка

AST-ноды

КлассОписаниеeval_masks()
TermNodeЛист — подстрокаПоиск в _buf_lower → булева маска строк
AndNodeleft AND rightleft_mask & right_mask
OrNodeleft OR rightleft_mask | right_mask
NotNodeNOT child~child_mask

Парсер

_Parser — рекурсивный спуск. Грамматика:

or_expr    → and_expr (OR and_expr)*
and_expr   → not_expr ((AND | неявный) not_expr)*
not_expr   → NOT not_expr | primary
primary    → "терм" | (or_expr)

Результат кэшируется через @lru_cache в parse_query().

8. Поиск — SearchEngine

core/search_engine.py (~71 строка).

Как работает

  1. search(store, pipeline, pattern, mode, direction, start_line) создаёт временный Filter
  2. Вычисляет маску только среди видимых строк (в filtered_indices)
  3. Сохраняет результат в SearchState.matches
  4. Начальная позиция — ближайшее совпадение к start_line (выбранная строка в таблице)

Навигация

  • next_match() — следующее совпадение. Циклически: после последнего → первое
  • prev_match() — предыдущее. Циклически: перед первым → последнее
  • clear_search() — сброс
Поиск по видимым строкам: Не сканирует весь файл. Если фильтр показывает 1000 из 1 000 000 — обработает только 1000.

9. Подсветка

Аналогична фильтрам, но вместо скрытия — окрашивание совпадений.

Механизм

  1. Пользователь добавляет подсветку (:h error)
  2. Создаётся Highlight с pattern, mode и auto-assigned цветом
  3. При отрисовке ячеек таблицы модель проверяет каждую подсветку
  4. Совпавшие фрагменты окрашиваются в соответствующий цвет
  5. Цвета чередуются из палитры для различимости

В режиме поиска текущее совпадение подсвечивается (жёлтый фон) для визуального выделения.

10. Категории

Построение дерева

# Категории из лога:
app/main
app/network/http
app/network/ws
system/io

# Дерево:
root
± app
  ± main          (150)
  ± network
    ± http          (80)
    ± ws            (30)
± system
  ± io             (45)

Фильтрация

  • Каждый узел — флаг enabled
  • Отключение родителя → отключение всех потомков рекурсивно
  • Маска строится из disabled_categories
  • Строки с отключённой категорией исключаются из filtered_indices

Управление

  • :cate app/main — включить
  • :catd app/main — отключить
  • GUI: чекбоксы в дереве категорий на боковой панели

11. Табличная модель

gui/log_table.py. Связь между LogStore и Qt.

LogTableModel

  • Источник: LogStore.filtered_indices
  • Ленивая загрузка: данные через RowRef → LogStore.get_columns() при отображении
  • Columns: Timestamp, Category, Level, Message
  • Подсветка: Qt.BackgroundRole проверяет highlights и search match

LogTableView

  • Vim-навигация: j/k, g/G, Ctrl-U/Ctrl-D
  • Виртуальный скроллинг: Qt рендерит только видимые строки
  • Контекстное меню: копирование, пин/анпин
  • Сохранение позиции: при обновлении фильтров

update_indices()

  1. Сохраняет текущую выделенную строку
  2. Обновляет массив индексов
  3. Эмитит layoutChanged
  4. Восстанавливает выделение на ближайшую строку

13. Оптимизации производительности

Буфер байтов

Единый bytearray для всего файла. Декодирование только при отображении.

Память

SoA + NumPy

Массивы uint8, uint16, uint64 вместо Python-объектов. Векторизованная фильтрация.

Скорость

Cython-парсинг

scan_line_starts_fast() и parse_batch_fast() — до 50x быстрее чистого Python.

Парсинг

Бинарный поиск

np.searchsorted() для маппинга позиций на строки — O(log n).

Алгоритм

Кэш lowercase

_buf_lower — один раз создаётся, используется всеми поисками.

Память

Кэш термов

_term_cache предотвращает повторный поиск одинаковых подстрок.

Скорость

Ленивый рендеринг

Qt TableView рендерит только видимые строки (~50-100 из миллионов). Данные извлекаются через RowRef → LogStore.get_columns() по запросу делегата.

Фоновая загрузка

Чтение и парсинг в FileLoaderThread (QThread). GUI остаётся отзывчивым. Сигнал передаёт данные в главный поток.

14. Полный поток данных

Файл на диске → FileLoaderThread → bytes → LogStore._buf
↓ Парсинг (Cython / Python fallback)
line_starts[] + category_ids[] + levels[] → SoA-массивы
↓ _finalize_load()
Category tree + Level counts → pipeline.apply()
↓ Фильтрация
cat_mask & level_mask & filter_mask | pin_mask → filtered_indices
↓ Отображение
LogTableModel → RowRef(idx) → LogStore.get_columns(idx)
↓ Парсинг одной строки по запросу
parse_columns() → (ts, cat, level, msg) → Ячейки таблицы

Цикл обновления при взаимодействии

:f error — команда фильтра
LogStore.add_filter() → Pipeline.add_filter() → pipeline.apply()
↓ Пересчёт filtered_indices
model.update_indices() → layoutChanged → TableView перерисовывается
↓ Обновление UI
Level buttons + Status bar + Category tree
