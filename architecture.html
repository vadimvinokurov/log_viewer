1 Общая архитектура

Проект построен по паттерну, близкому к MVP (Model-View-Presenter). Логика полностью отделена от GUI: модуль core/ не импортирует Qt, модуль gui/ только отображает данные и реагирует на действия пользователя. Координатором выступает MainWindow.

Пользователь → MainWindow (GUI) → CommandParser → LogStore (core)
LogStore → FilterEngine → SimpleQuery → filtered_indices[]
filtered_indices[] → LogTableModel → LogTableView

core/ — модель и логика

models.py — дата-классы данных

parser.py — парсер лог-строк

log_store.py — центральное хранилище SoA

filter_engine.py — движок сопоставления

simple_query.py — булев язык запросов

command_parser.py — парсер команд

gui/ — Qt-виджеты

app.py — MainWindow, координация

log_table.py — модель и представление таблицы

side_panel.py — боковая панель

bottom_bar.py — статус + ввод команд

highlight_delegate.py — делегат подсветки

styles.py — QSS-стили (единый источник)

2 Загрузка файлов

Файлы загружаются в три этапа: чтение в фоновом потоке, пакетный парсинг, перестроение индексов.

2.1 Фоновое чтение

Класс _FileLoadWorker (QThread) считывает файл целиком в bytearray через Path.read_bytes(). Это позволяет не блокировать GUI. После завершения испускается сигнал loaded(buf, path).

2.2 Приём в MainWindow

Слот _on_file_loaded() передаёт буфер в LogStore.load_bytes(), удаляет свою ссылку на буфер (LogStore хранит свою копию) и вызывает _refresh_display() для обновления всех виджетов.

2.3 Внутри LogStore.load_bytes()

bytearray → scan_line_starts_fast() → detect_format_bytes() → parse_batch_fast()
parse_batch_fast() → Cython / Python fallback → numpy-массивы

Способы открытия файла: диалог (Ctrl+O), drag & drop, аргумент командной строки, команда :open <path>.

3 Парсер логов

Поддерживаются два формата. Автоопределение происходит по первой непустой строке.

KSIVA (основной)

timestamp category [LOG_LEVEL] message

Разбиение по пробелам (maxsplit=3). Позиция 2 проверяется на LOG_* — если найдена, это уровень; иначе сливается с позицией 3 в сообщение, уровень = INFO.

PLAIN

timestamp elapsed level_short category message

Разбиение по пробелам (maxsplit=4). Короткие коды уровней: wrn/msg/dbg/err/crt. Поле elapsed отбрасывается.

3.1 Пакетный парсинг (parse_batch_fast)

Вместо создания Python-объектов на каждую строку, парсер заполняет numpy-массивы напрямую. Есть Cython-ускоритель (_parser_cy); если он не скомпилирован — fallback на чистый Python. 

# Возвращаемые массивы:
timestamp_spans : ndarray[SPAN_DTYPE]  # (offset, length) в байтовом буфере
category_ids     : ndarray[uint16]      # ID категории (индекс в _category_names)
levels           : ndarray[uint8]       # 0=CRITICAL .. 5=TRACE
message_spans    : ndarray[SPAN_DTYPE]  # (offset, length) в байтовом буфере

3.2 Сканирование границ строк

Функция scan_line_starts_fast() использует numpy для SIMD-обнаружения символов \n. Возвращает массив uint64 длины n+1: строка i = buf[starts[i]:starts[i+1]].

3.3 Дефолтные значения

  • Пустая строка → категория "uncategorized", уровень INFO, пустое сообщение
  • Отсутствует уровень → INFO
  • Отсутствует категория → "uncategorized"
  • Строки интернированы через sys.intern() для экономии памяти

4 Хранилище данных (LogStore)

LogStore — центральное хранилище, построенное по архитектуре Structure of Arrays (SoA). Вместо списка Python-объектов данные хранятся в одном байтовом буфере + набор numpy-массивов индексов.

4.1 Буфер и массивы

class LogStore:
    _buf            : bytearray       # Единый буфер всего файла
    _buf_lower      : bytes | None    # Кэш buf.lower() для быстрого поиска
    n               : int             # Количество строк

    # SoA-колонки (длины n):
    timestamp_spans : ndarray[SPAN_DTYPE]  # (offset, length) в _buf
    category_ids    : ndarray[uint16]      # ID категории
    levels          : ndarray[uint8]       # ID уровня
    message_spans   : ndarray[SPAN_DTYPE]  # (offset, length) в _buf
    line_starts     : ndarray[uint64]      # Границы строк (длина n+1)

    # Фильтрация:
    filtered_indices: ndarray[uint32]      # Индексы видимых строк
    _filter_masks   : list[ndarray[bool]]  # Маска на каждый фильтр
    _pin_masks      : list[ndarray[bool]]  # Маска на каждый pin

4.2 Ленивый доступ к данным

Сообщения и таймстемпы не декодируются при загрузке. Вместо этого get_message(i) читает срез _buf[offset:offset+length] и декодирует в UTF-8 по запросу. Для GUI это прозрачно через прокси-объект RowRef.

4.3 RowRef — лёгкий прокси

RowRef хранит только индекс строки + ссылку на LogStore. Свойства (message, timestamp, category, level) вычисляются на лету. Создаётся ~50 штук для видимых строк, не хранится в bulk.

6 Движок фильтрации (FilterEngine)

Модуль filter_engine.py предоставляет два типа операций: проверка совпадения и поиск спанов.

6.1 Режимы сопоставления

РежимОписаниеАлгоритм
PLAIN Подстрока (без учёта регистра) pattern.lower() in text.lower()
REGEX Регулярное выражение (IGNORECASE) re.search(pattern, text, IGNORECASE)
SIMPLE Булев запрос AND/OR/NOT Парсинг в AST → ast.evaluate(text)
LINE_NUMBER Точная строка по номеру idx = int(pattern) - 1

6.2 Пакетное сопоставление (batch_match)

Все PLAIN-фильтры объединяются в один компилированный regex через альтернацию: re.compile("|".join(escaped_patterns)). Это O(n) вместо O(n*m). Остальные фильтры применяются индивидуально.

6.3 Буферный поиск в LogStore

В _compute_filter_mask() поиск идёт не по отдельным строкам, а по всему буферу целиком:

  1. Выполняется regex.finditer(buf_lower) — получаем все позиции совпадений
  2. np.searchsorted(msg_offsets, positions) — маппим позиции на строки за O(n log n)
  3. Проверка, что совпадение попало в пределы сообщения (offset ≤ pos < offset + length)
  4. Устанавливаем mask[line_idx] = True

Для SIMPLE-запросов каждый терм ищется отдельно, затем маски комбинируются через AND/OR/NOT numpy-операции.

7 Язык запросов Simple Query

Рекурсивный descent-парсер с LRU-кэшем (256 записей).

7.1 Грамматика

expression := or_expr
or_expr    := and_expr ("OR"  and_expr)*
and_expr   := not_expr ("AND" not_expr)*
not_expr   := "NOT" not_expr | primary
primary    := "(" expression ")" | STRING
STRING     := '"' ... '"'

Приоритет: NOT > AND > OR. Все строки обязаны быть в двойных кавычках.

7.2 AST-узлы

Узелevaluate()find_spans()eval_masks()
TermNode(text) Подстрока в тексте Все (start, end) term_masks[text]
AndNode(left, right) left AND right Объединение спанов left & right
OrNode(left, right) left OR right Объединение спанов left | right
NotNode(child) NOT child Пустой список ~child

7.3 Примеры

"error" AND "timeout"          # Оба терма в строке
"error" OR "warning"            # Хотя бы один терм
NOT "info"                       # Строка не содержит "info"
("a" OR "b") AND NOT "c"        # Сложное выражение

8 Поиск

8.1 Полный поток поиска

Пользователь: :s pattern → CommandParser → MainWindow._do_search()
_do_search() → LogStore.search() → _compute_filter_mask()
mask[filtered_indices] → SearchState.matches[] → _jump_to_search_match()

8.2 Логика поиска

  1. Строится маска совпадений для ВСЕХ строк (_compute_filter_mask)
  2. Маска пересекается с текущими filtered_indices — поиск только среди видимых строк
  3. Совпадения сохраняются в SearchState.matches как список абсолютных индексов
  4. Стартовая позиция — строка под курсором (selectedRows()) или 0
  5. bisect_left() определяет ближайшее совпадение к старту

8.3 Навигация

После входа в режим поиска (in_search = True):

  • ↓ → next_match() — переход к следующему совпадению (циклический)
  • ↑ → prev_match() — переход к предыдущему совпадению
  • Esc → выход из режима поиска

Навигация использует модульную арифметику: (current_index ± 1) % len(matches).

9 Фильтрация и видимые строки

9.1 Иерархия фильтров

Итоговая видимость строки определяется формулой:

visible = Pinned OR (Category AND Level AND TextFilters)

Pin-правила обходят ВСЕ остальные фильтры — закреплённая строка видна всегда.

9.2 _apply_filters() — метод пересчёта

  1. Category mask: np.isin(category_ids, enabled_ids)
  2. Level mask: np.isin(levels, enabled_level_ids)
  3. Text mask: OR всех активных _filter_masks
  4. Combined: cat_mask & level_mask & text_mask
  5. Pin mask: OR всех активных _pin_masks
  6. Result: combined = combined | pin_mask
  7. filtered_indices = np.where(combined)[0]

9.3 Кэширование масок

Каждый фильтр хранит предвычисленную маску в _filter_masks. При добавлении/удалении фильтра маска пересчитывается только для него. При перезагрузке файла все маски перестраиваются через _recompute_all_filter_masks().

9.4 Подсчёт уровней

level_button_counts — количество строк каждого уровня с учётом категорий и текстовых фильтров, но без учёта переключателей уровней. Это позволяет кнопке показывать "скрытое" количество. Используется np.bincount() для быстрого подсчёта.

10 Подсветка

10.1 Поток подсветки

:h pattern → LogStore.add_highlight() → HIGHLIGHT_PALETTE[color_idx]
Highlight(color, pattern, mode) → HighlightDelegate.paint() → Цветной фон в таблице

10.2 Рендеринг

HighlightDelegate (QStyledItemDelegate) перехватывает отрисовку ячеек. Для каждого видимого правила подсветки вызывается filter_engine.find_spans(), который возвращает список пар (start, end). Делегат рисует цветные прямоугольники под текстом.

10.3 Цвета

Цвета назначаются циклически из палитры HIGHLIGHT_PALETTE. Счётчик _highlight_color_index инкрементируется при каждом добавлении. Цвет можно сменить через GUI (color picker в боковой панели).

11 Категории

11.1 Извлечение

Категории извлекаются из поля category каждой лог-строки. Иерархические пути разделены символом / (например, app/main, network/tcp/ssl).

11.2 Дерево

Дерево строится в _build_category_tree():

  1. np.unique(category_ids, return_counts=True) — подсчёт каждой категории
  2. Имя категории разбивается по /
  3. Каждый сегмент становится узлом CategoryNode, если его ещё нет
  4. Каждый узел накапливает line_count

11.3 Фильтрация по категориям

В GUI — QTreeWidget с чекбоксами. При изменении чекбокса:

  1. CategoryTreeWidget собирает отключённые пути
  2. Вызывается LogStore.set_disabled_categories(paths)
  3. Маски пересчитываются через _set_enabled_recursive()
  4. Вызывается _apply_filters()

Поддерживаются wildcard-шаблоны (*) в командах :cate и :catd. При перезагрузке файла отключённые категории восстанавливаются по имени (новым ID).

12.1 Парсер

Команда вводится после : в нижней панели. Формат: name text или просто name (для zero-arg команд).

13.2 LogTableModel

Наследует QAbstractTableModel. Не хранит данные — работает как маппинг filtered_indices → колонки таблицы.

  • 4 колонки: Line (номер), Time, Category, Message
  • DisplayRole: данные из LogStore через индекс
  • ForegroundRole: цвет текста по уровню (красный для ERROR и т.д.)
  • UserRole: возвращает RowRef для произвольного доступа

13.3 update_indices() — умное обновление

При обновлении модели:

  1. Сохраняет выделенные строки (по line_number) и позицию viewport
  2. Вызывает beginResetModel() / endResetModel()
  3. Восстанавливает выделение на тех же строках
  4. Восстанавливает позицию прокрутки

Если индексы не изменились — short-circuit (нет перерисовки).

13.4 Контекстное меню

Правый клик на выделенных строках: Copy, Pin, Unpin (в зависимости от состояния).

13.5 Стили

14 Оптимизации производительности

SoA + byte buffer

Данные хранятся в одном bytearray + numpy-массивы индексов. Нет Python-объектов на каждую строку. Декодирование UTF-8 — только по запросу.

Кэш lowered buffer

_buf_lower = bytes(_buf).lower(). Вычисляется один раз, используется для всех PLAIN-поисков. Инвалидируется при загрузке нового файла.

numpy-векторизация

Фильтрация через np.isin(), np.where(), np.searchsorted(), np.bincount(). Boolean mask operations (&, |, ~) на всём массиве за один вызов.

Буферный regex

Regex применяется ко всему буферу за один finditer(), затем позиции маппятся на строки через binary search. Вместо N regex-вызовов — один.

Cython-парсер

_parser_cy — Cython-версия батчевого парсера. Компилируется автоматически при установке через setuptools. Fallback на чистый Python.

SIMD line scanning

scan_line_starts_fast() использует np.where(arr == 10) для поиска переносов строк. NumPy задействует SIMD-инструкции процессора.

Сводка потока данных

Файл на диске → bytearray (QThread) → numpy line_starts
numpy line_starts → Cython/Python batch parse → 5 numpy-массивов + buf
buf + regex.finditer → searchsorted + boolean masks → filtered_indices
filtered_indices → LogTableModel.data() → QTableView (ленивый рендер)
