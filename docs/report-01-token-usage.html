  • Fresh input dominates (95 k tokens/turn average, 153 k worst). On this backend every turn re-reads the whole context at full price. Cutting context size (shorter sessions, leaner system prompt, fewer loaded skills) is worth ~8× vs the same tokens served from cache — it is the one lever that matters most.
  • Replay tail is the second lever: 9785223c averaged 161 k replay tokens per turn because the visible conversation grew for 9 hours with screenshots and 100-line file reads in it. CLAUDE.md 7's "end turn at checkpoints" exists because of exactly this session's shape.
  • Images: 58 Read calls on PNG/JPG, 14.5 MB of base64 in results; f3da036d read the same golden PNG six times (1.67 MB), 405193b3 spent 4.8 MB in one session on screenshots and goldens. Full-window shots at 2800×1800 are the most expensive single reads in the history.
  • Degenerate loops: 359 calls were part of 3-or-more-repeat consecutive runs (10.9 % of all main-conversation tool calls). Worst: 24 consecutive edits of FUNCTIONAL_SPEC.html, 27× the identical live-check bash wrapper, 14× a python3-heredoc edit of live_check.mjs, 7× heredoc fights against a design script, 13× the identical git show. The driver.rs heredoc fight that produced CLAUDE.md 7's ban is one entry in a wider pattern: every long same-tool run ends the same way — with a wholesale rewrite of the file.
  • Gates: ~397 vitest/cargo/build/e2e/clippy bash calls in the coordinator, 117 in 9785223c alone (48 cargo, 29 build, 28 vitest, 10 clippy) — several identical back-to-back. Scoped-gate discipline (run one module's file while iterating) is paying off but was applied late in long sessions.
  • Recurring background noise: the beads export diff (20–33 KB) appeared as a large tool result in 7 of 15 sessions — an avoidable fixed cost of every bd sync-touching command; the agent-brief, once written, dropped agent prompts from ~1 k tokens to ~30 lines and is the best-verified saving on record.

4. Recommendations to cut consumption

Already on the books (keep enforcing)

CLAUDE.md 7Short turns at milestones · agent prompts point at docs/notes/agent-brief.md · numbers instead of screenshots · scoped gates between steps · cap agents · no heredoc edits. Each of the six has a measured failure in this data set; each also has a measured success (the 40–60 k band of well-briefed module agents). They are written as prose, and the mistakes report shows prose decays in long sessions — treat them as the fallback, mechanisms as the default (next section).

New, in order of expected effect

  1. Keep the coordinator conversation small at all times. This is the 85 %-driver. Practically: /clear or a fresh session at every task boundary; a task is a bead id, and the coordinator reads the bead + the returning summary, not the files; large reads (full files, docs, transcripts) belong in agents. A mid-size coordinator conversation of ~40 turns at 95 k input costs ~4 M units per turn-set; the same work relaunched per milestone would cost a fraction.
  2. Never re-read a file for one detail. The dominant avoidable Read pattern is same-file 3–6× reads (ipc.rs ×3, golden loaded.png ×6, uiConsole.ts ×4). Rule for the coordinator: read a file once, keep the relevant block in the plan (bead description), and delegate all later looks at that file to the agent that owns the change.
  3. Kill loops mechanically at the third identical failure. The 359 lost calls are mostly 20–50-minute loops that a "rewrite the file wholesale" would have ended in 2 calls. This is the one rule worth a hook, not prose: a post-tool-use guard that flags the third consecutive same-tool call and forces an alternative route. See the mistakes report — three of top loss drivers are loop-shaped.
  4. Pictures are for visual acceptance only (already rule 4) — the data adds: also never re-read the same golden twice; the diff % already answers "did it change", and the harness's text diffs answer more than a second read.
  5. Trim the fixed background cost. Suppress the 20–33 KB beads export diff from appearing in coordinator context (redirect bd export noise to agents or set the export to run at session close); keep the coordinator's system-prompt side small (fewer auto-loaded skills per session; the kit's using-skills hook adds a full rule text to every session — make that hook 5 lines, not a full skill text).
  6. Batch gates at natural boundaries — the ~397 gate calls include several full-workspace reruns less than an hour apart. The checkpoint-commit pattern pairs with a fixed one-shot "full gate before commit" (rule 9), and scoped single-file gates everywhere else.

6. Recommended way of working with agents (this project, next 30 days)

  1. Coordinator: task boundary → /clear → bd ready → claim → read bead + brief + spec section (one screen max) → spawn agent with pointer-prompt + budget → receive summary → run the one scoped gate needed to trust it → close bead → commit → end turn.
  2. Agents get: bead id, agent-brief pointer, ≤3 files, the exact gate commands, the token budget line, and the checkpoint instruction. Nothing else inline.
  3. Two gates maximum per coordinator turn; visual checks via npm run e2e diff percentages and the design oracle, images only when a human decision is needed.
  4. Keep the 40–60 k agent band as the target; treat any agent > ~100 M raw tokens as a process bug: stop it, capture its notes from bd update, decompose the bead.
