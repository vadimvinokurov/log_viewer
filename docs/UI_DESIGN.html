Main window

The canonical state: file loaded, default layout. The Categories sidebar stands open on the right by default (§10) and hides only by demand — Ctrl+B. The table takes the whole window under a 30-px titlebar and a 32-px bottom bar. Columns per §4 — Line Time Category Message, with Message taking everything that is left. Whole line is tinted by level (§3.1), line numbers and timestamps are dim: the eye should land on Message.

Categories panel

The Categories tab of the sidebar on its own (§10). Every checkbox state is shown: checked, unchecked, and the parent "partially enabled" tick; disabled categories are dimmed and take their whole subtree with them. The toggle beside the search field is expand-all / collapse-all (except root nodes); expansion state survives tree rebuilds. Right — the tree under an active search: a node stays visible if it matches or has a matching descendant, and the tree expands fully while the search is on. The third frame shows a list tab (§10.1) — checkbox, command text, delete ✕; the same anatomy holds for Filters, Highlights and Pinned.

Rationale

What the design commits to, and why.

  • The table is the app. Chrome is two hairline bars (30 px + 38 px); Message gets every remaining pixel. No tabs, no ribbon, no panel above the logs — ever.
  • The panel is furniture, not a mode. The Categories sidebar stands open, docked to the right edge (§10), and hides only by demand — Ctrl+B; its 280 px are fixed, Message flexes around it.
  • Color speaks only where data speaks. Neutrals are cool-slate and quiet; the only saturated color on a default screen is level tint and the accent selection.
  • Whole-line level coloring (§3.1) instead of a level cell: one glance down the edge of the screen shows the error distribution, and no column width is wasted on it.
  • Pin = gold dot, highlight = translucent behind spans (§9): both survive at 6.4 M rows because they cost no layout.
  • Chrome text in the system sans, data in the system fixed font — the split is visible at a glance: anything you read from the log file is the system mono, anything the app itself says is the system sans. No webfonts — the v1 Qt app used QFontDatabase system fonts and the design keeps that parity.
  • Density over comfort. Row is 21 px (system-mono glyph height + 6 px, v1 parity); zebra striping is faint and disappears on hover/selection, so scanning stays primary.
