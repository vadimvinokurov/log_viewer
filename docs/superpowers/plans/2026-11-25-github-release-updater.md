# GitHub Release builds + in-app auto-update — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pushing tag `vX.Y.Z` builds and publishes installable artifacts (`latest.json` included) via GitHub Releases, and installed builds (macOS + Windows, Tauri 2) self-update through `tauri-plugin-updater` with a startup auto-check and a manual `check-updates` cmdline command.

**Architecture:** the updater transport is the official plugin pair (`tauri-plugin-updater` + `tauri-plugin-process`) backed by `latest.json` from the latest GitHub Release, generated by `tauri-apps/tauri-action` on a tag-push workflow. Update *logic* is a pure module (`updates.ts`) reduced by the `UiConsole` store exactly like the existing cmdline slice (kept outside `state.ts`); the UI is one thin banner component reading the store via `useSyncExternalStore`. The updater plugin surface is a direct-binding seam (`UpdaterCommands`) resolved through `window.__ipcStub`, mirroring the existing `SettingsCommands` seam.

**Tech Stack:** Tauri 2.12.5 (`tauri-plugin-updater` 2, `tauri-plugin-process` 2), @tauri-apps/plugin-updater / plugin-process (npm), tauri-apps/tauri-action@v0 GitHub Action, vitest + the committed render-to-PNG harness (`ui/e2e/render.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-25-github-release-updater-design.md` (owner decisions: unsigned builds, universal macOS dmg, NSIS x64 Windows, auto-check at startup + manual, fresh keypair, version stays 0.1.0, agent does the full pipeline incl. secrets via `gh secret set` and the tag push — the owner's explicit «сделай все сам»).

## Global Constraints

- Version source of truth: `src-tauri/tauri.conf.json` `"version": "0.1.0"`; tag must equal it (`v0.1.0`).
- Updater endpoint (exact): `https://github.com/vadimvinokurov/log_viewer/releases/latest/download/latest.json` (config list form: `["https://…/latest.json"]`).
- Builds stay **unsigned** (no Developer ID / Authenticode); only the Tauri minisign updater signature is used.
- macOS target `universal-apple-darwin` (single dmg, aarch64 + x86_64); Windows NSIS x64.
- npm only (never pnpm); run all JS gates from the `ui/` directory; vitest single-module loop while iterating, full gates once before commit (rule 7).
- `test_logs/` content never appears anywhere (rule 1); project files in English; commits in English with `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
- UI work headless-first (rules 4–5): vitest for logic, `window.__headless` snapshots for state, golden PNGs via `npm run e2e` for rendered states; no OS screenshots.
- Unit stubs mirror the RAW IPC shapes exactly; the only seam resolution point is `window.__ipcStub` (rule 4).
- The updater is the app's only network call (deliberate exception to spec §1's «no networking»): every updater failure path must leave the app fully usable.

## Review Focus

Failures the spec implies but no single task's happy-path tests exercise — each is pinned by the test named here:

1. **Offline / network error at startup auto-check** — the app must keep working with no visible trace. Test: stub `check()` rejects, source `"auto"` → `update` stays `initialUpdateState()` (`updated.test` in Task 3: `autoCheckFailureStaysSilent`).
2. **404 before the first release exists** — same silent path as (1); covered by the same test with `"404"` as the rejection message.
3. **Manual check or install failure** (tampered payload, signature rejection, HTTP error) — banner shows `Update failed: …`, app alive, Retry works. Tests: `manualCheckFailureShowsError` and `installFailureShowsError` (Tasks 2–3); rendered once in e2e state `27-update-failed`.
4. **Version comparison quirks** — `1.2` vs `1.2.0` equal; `1.20.0` > `1.3.0` (numeric, not lexicographic); a release outranks its own prerelease (`1.0.0` > `1.0.0-rc.1`). Tests in Task 2.
5. **Re-check storm** — `checkForUpdates` while already `checking`/`available`/`downloading` must not restart state. Test: `recheckWhileBusyIsNoop` (Task 2, via `reduceUpdate` guard).

### Task 2: Pure update module `updates.ts`

**Files:**
- Create: `ui/src/updates.ts`
- Test: `ui/src/updates.test.ts`

**Interfaces:**
- Produces (consumed by Tasks 3–4):
  - `type UpdatePhase = "idle" | "checking" | "available" | "downloading" | "installed" | "uptodate" | "failed"`
  - `type UpdateSource = "auto" | "manual"`
  - `interface UpdateState { phase: UpdatePhase; source: UpdateSource; availableVersion: string | null; error: string | null }`
  - `function initialUpdateState(): UpdateState` (`{phase: "idle", source: "auto", availableVersion: null, error: null}`)
  - `type UpdateEvent = { kind: "update-check-start"; source: UpdateSource } | { kind: "update-available"; version: string } | { kind: "update-none" } | { kind: "update-download-start" } | { kind: "update-installed" } | { kind: "update-failed"; error: string } | { kind: "update-dismiss" }`
  - `function reduceUpdate(state: UpdateState, event: UpdateEvent): UpdateState`
  - `function compareVersions(a: string, b: string): number` (−1/0/1; three-component semver core, numeric per segment, missing segments = 0; a release outranks its own prerelease suffix)
  - `function bannerVisible(state: UpdateState): boolean` (true for `available`/`downloading`/`installed`/`uptodate`/`failed`; false for `idle`/`checking`)

- [ ] **Step 1: Write the failing tests** (`ui/src/updates.test.ts`)

Cover, at minimum:

```ts
it("compareVersions is numeric and length-tolerant", () => {
  expect(compareVersions("1.2.0", "1.2")).toBe(0);
  expect(compareVersions("1.20.0", "1.3.0")).toBe(1);   // Review Focus 4
  expect(compareVersions("0.2.0", "0.1.0")).toBe(1);
  expect(compareVersions("1.0.0", "1.0.0-rc.1")).toBe(1);
});
it("manual check yields available then uptodate when nothing found", () => {
  let s = reduceUpdate(initialUpdateState(), {kind: "update-check-start", source: "manual"});
  expect(s.phase).toBe("checking");
  s = reduceUpdate(s, {kind: "update-available", version: "0.2.0"});
  expect(s).toMatchObject({phase: "available", availableVersion: "0.2.0"});
  s = reduceUpdate(s, {kind: "update-none"});
  expect(s.phase).toBe("uptodate");
});
it("auto check stays silent on failure (Review Focus 1)", () => {
  // reducer keeps "failed"; the AUTO silence rule is pinned in Task 3's
  // console test — the reducer itself records the failure source-honestly.
  let s = reduceUpdate({...initialUpdateState(), source: "auto"},
    {kind: "update-check-start", source: "auto"});
  s = reduceUpdate(s, {kind: "update-failed", error: "404"});
  expect(s.phase).toBe("failed");
});
it("recheck while busy is a no-op (Review Focus 5)", () => {
  const busy = reduceUpdate(initialUpdateState(),
    {kind: "update-check-start", source: "manual"});
  const available = reduceUpdate(busy, {kind: "update-available", version: "0.2.0"});
  const restarted = reduceUpdate(available, {kind: "update-check-start", source: "auto"});
  expect(restarted).toEqual(available);
  const downloading = reduceUpdate(available, {kind: "update-download-start"});
  expect(reduceUpdate(downloading, {kind: "update-check-start", source: "manual"}))
    .toEqual(downloading);
});
it("dismiss resets everything", () => {
  const s = reduceUpdate({phase: "failed", source: "manual", availableVersion: "0.2.0", error: "boom"},
    {kind: "update-dismiss"});
  expect(s).toEqual(initialUpdateState());
});
```

Guard rules inside `reduceUpdate` (pin these in the tests above): `update-check-start` is accepted only from `idle`/`failed`/`uptodate` and resets `error`/`availableVersion`; `update-available` applies only while `checking`; `update-download-start` only from `available`; `update-none` from `checking` maps auto→`idle`, manual→`uptodate`; `update-failed` applies from `checking`/`downloading`.

- [ ] **Step 1: Write `.github/workflows/release.yml`**

```yaml
name: release
on:
  push:
    tags: ["v*"]
permissions:
  contents: write
jobs:
  gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: swatinem/rust-cache@v2
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci --prefix ui
      - run: cargo test --workspace
      - run: npm --prefix ui run build
      - run: npm --prefix ui test -- run
      - run: npm --prefix ui run e2e   # verify the real script name in ui/package.json first (rule 7: run from ui/)
  build:
    needs: gate
    strategy:
      fail-fast: false
      matrix:
        include:
          - { os: macos-latest, args: "--target universal-apple-darwin" }
          - { os: windows-latest, args: "" }
    runs-on: ${{ matrix.os }}
    defaults: { run: { shell: bash } }
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with: { targets: "aarch64-apple-darwin,x86_64-apple-darwin" }
      - uses: swatinem/rust-cache@v2
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci --prefix ui
      - name: tag must equal tauri.conf.json version
        run: |
          tag="${{ github.ref_name }}"
          version="v$(jq -r .version src-tauri/tauri.conf.json)"
          [ "$tag" = "$version" ] || { echo "tag $tag != config $version"; exit 1; }
      - uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
        with:
          tagName: ${{ github.ref_name }}
          releaseName: logviewer ${{ github.ref_name }}
          releaseDraft: false
          prerelease: false
          args: ${{ matrix.args }}
```
