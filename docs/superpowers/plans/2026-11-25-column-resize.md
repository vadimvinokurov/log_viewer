# Column Resize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drag column borders in the table header to resize all four columns (min 20px), with rubber-band Message, double-click reset, and persistence across restarts.

**Architecture:** Pure widths math in `ui/src/columnWidths.ts`, widths state in the existing app reducer (ConsoleSnapshot), drag wiring in LogTable (thin), persistence through the existing settings IPC seam (`settings_get` / new `set_column_widths` over `logviewer-core/settings::Store`).

**Tech Stack:** React + vitest (UI), tauri-specta (IPC bindings regenerated by cargo test), custom settings store in `crates/logviewer-core`.

**Spec:** `docs/superpowers/specs/2026-11-25-column-resize-design.md` (owner-approved 2026-11-25); §4 of `docs/FUNCTIONAL_SPEC.html` for the default widths.

## Global Constraints

- Every column min width: **20px** (design decision).
- Default widths: **50 / 110 / 150 / 600** (spec §4).
- Message effective width: `max(user width, viewport − other three, 20px)` — while the user-sum fits the window, the table fills it exactly.
- All new UI logic is pure-module + vitest; components only wire (CLAUDE.md rule 4). Imports in `ui/src` use explicit `.tsx` extensions for components (case-insensitive-FS trap).
- IPC: schema-driven bindings only — `specta` derives, commands registered in `src-tauri/src/lib.rs::collect_commands`, `ui/src/bindings.ts` regenerated by cargo tests, never hand-edited.
- Scoped test runs from the config's own directory: vitest **from `ui/`**, cargo from repo root. Full gates (all vitest + all cargo + `npm run e2e`) once at the final task.
- Commits per task in the repo's style (`feat(ui): ...`).

## Review Focus

The five inputs most likely to bite, each pinned by a test named here:

1. **Drag handles leak listeners** — mouseup outside the webview must end the drag; listeners attach to `window` and detach on `mouseup` (Task 5's drag wiring; pinned by the e2e state asserting widths stop after mouse up).
2. **Hidden Message user-width** — dragging Message below the window remainder stores a small user width; a later window change must never resurrect it as overflow (effective ≥ remainder always). Pinned by `effectiveWidths` tests (Task 1).
3. **Hostile persisted data** — persisted widths of null, wrong length, or non-numeric/garbage values round-trip to defaults without throwing (Task 1's `parseColumnWidths`, Task 3's tolerant Rust decode).
4. **Resize must not move the vertical scroll** — rows are absolutely positioned; `scrollTop` and the anchor must be identical before/after a width change. Pinned by the e2e state `column-resized` (Task 6).
5. **Overflow model** — the horizontal scrollbar area exists only when the *user*-width sum exceeds the viewport, never while Message fills the remainder. Pinned by `effectiveWidths` + the e2e `column-overflow` state (Tasks 1, 6).

### Task 1: Pure widths module `columnWidths.ts`

**Files:**
- Create: `ui/src/columnWidths.ts`
- Test: `ui/src/columnWidths.test.ts`

**Interfaces:**
- Consumes: nothing.
- Produces (Tasks 2–6 import these):
  ```ts
  export type ColumnKey = "line" | "time" | "category" | "message";
  export interface ColumnWidths { line: number; time: number; category: number; message: number }
  export const COLUMN_KEYS: readonly ColumnKey[];
  export const DEFAULT_COLUMN_WIDTHS: ColumnWidths; // { line: 50, time: 110, category: 150, message: 600 } (§4)
  export const MIN_COLUMN_PX = 20;
  export function clampWidth(px: number): number;          // Math.round + clamp to [20, ∞), NaN/Infinity → 20
  export function setWidth(widths: ColumnWidths, key: ColumnKey, px: number): ColumnWidths;   // immutable
  export function resetWidth(widths: ColumnWidths, key: ColumnKey): ColumnWidths;             // back to default
  export function effectiveWidths(widths: ColumnWidths, viewportWidth: number): ColumnWidths;
  export function columnTotal(ws: ColumnWidths): number;
  export function columnGridTemplate(ws: ColumnWidths): string; // "50px 110px ...", integers
  export function parseColumnWidths(raw: unknown): ColumnWidths; // null/garbage → defaults; arrays of 4 → clamped
  export function serializeColumnWidths(ws: ColumnWidths): [number, number, number, number];
  ```

- [ ] **Step 1: Write the failing test** — `columnWidths.test.ts` covering:
  - `clampWidth`: 19.4 → 20; 600 → 600; NaN → 20; -5 → 20.
  - `setWidth`/`resetWidth`: immutability (input object unchanged), exact clamped value, unknown-key type safety is compile-time only.
  - `effectiveWidths` (defaults = others 310):
    - defaults, viewport 1400 → message 1090, total 1400 (fills the window);
    - user message 1200, viewport 1400 → message 1200, total 1510 (overflow);
    - line 1000, time 20, category 20, message 600, viewport 900 → message 600, total 1640 (others overflow);
    - user message 20, viewport 330 → message 20, total 330 (exact fit, 20px floor holds);
    - the Review Focus case: user message 30 stored, viewport 1400 → effective 1090 (remainder wins, never the 30).
  - `parseColumnWidths`: `null` → defaults; `[60,120,160,620]` → same; `[0,0,0,0]` → all 20; `[60.4,120,160,"x"]` as unknown → all defaults (hostile); 3-entry array → defaults.
  - `columnGridTemplate(effectiveWidths(DEFAULT_COLUMN_WIDTHS, 1400))` === `"50px 110px 150px 1090px"`.
- [ ] **Step 2: Run to verify it fails** — from `ui/`: `npx vitest run src/columnWidths.test.ts` → FAIL (module not found).
- [ ] **Step 3: Implement the module** — the formulas above; no viewport/DOM imports.
- [ ] **Step 4: Run to verify pass** — same command, PASS.

- [ ] **Step 1: LogTable integration.**
  - Viewport width via a `useState` + `useResizeObserver`-style `ResizeObserver` on `scrollRef` (state `vw`, set on the container; initial layout effect read).
  - `const effective = effectiveWidths(columnWidths, vw)`; header and every row get `style={{ gridTemplateColumns: columnGridTemplate(effective), width: columnTotal(effective) }}`; `.table-inner` gets `minWidth: columnTotal(effective)` inline; remove the CSS fixed template + fixed min-widths (`min-width: 830px` must be gone — it would force overflow below 830px otherwise).

    - `dblclick`: `preventDefault` + `stopPropagation`, `onColumnReset(key)`.
  - The Message handle stops visually at the remainder (effective clamp in markup) while the stored user width may dip below it — intended, per design (Review Focus 2).
