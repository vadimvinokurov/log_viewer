2. The four real appetite drivers

  • Coordinator-context replay (largest). Every turn re-pays the whole visible conversation. Long turns, many screenshots (I read ~10 window/page PNGs, several at full window size), and 100-line file reads after every edit grew a tail that is paid again each time.
  • Duplicated context in agent prompts. Each agent prompt restated spec semantics inline (the §-sections I had already decoded) and pointed agents at 4–6 files to "read first". Correctness yes, but the same semantics were paid 9+ times across agents.
  • Degenerate tool loops (the worst per-idea waste). The driver.rs escaping fight: 5–6 python-heredoc attempts with mangled quoting, each round costing a full read+edit cycle, before rewriting the tail of the file wholesale — which worked on the first try.
  • Process churn: four consecutive e2e-fixture dead-ends and three dev-server relaunch cycles (tauri-driver dead ends, dialog automation dead ends), plus full cargo test --workspace + clippy runs repeated between micro-steps where a scoped run would answer.

3. Proposals to cut the appetite

  • End turns at checkpoints; keep turns short. The coordinator replay is quadratic in turn count: closing the turn after committing a milestone (and letting the next turn start fresh on a compaction summary) materially lowers replay cost. Commit-per-milestone also makes 429 interruptions harmless.
  • Single shared agent brief instead of inline spec re-decoding. Commit a docs/notes/agent-brief.md once (the per-layer rules, file-partition conventions, style, TDD/gates, the case-insensitive-import trap) and let agent prompts point at it + the one bead id: prompts drop from ~1k tokens to ~30 lines.
  • Never debug by shell-escaping into files. Rule for me: a second failed sed/heredoc edit → stop and rewrite the whole file with the Write tool. This alone would have saved tens of thousands of tokens in the driver work.
  • Numbers instead of screenshots. Non-visual checks (element present, sizes, counts) go through evaluate text results; Read-on-PNG only for visual acceptance, and at element scope instead of the full window (a full-window shot at 2800×1800 is one of the most expensive single reads in the session).
  • Scoped gates between steps, full gates once at integration. cargo test -p <crate> --lib <module> answers for a module; the full workspace suite runs once before a commit, not after every micro-edit.
  • Cap and checkpoint agents. Visibility-engine work (79k) grew because one task carried engine + counters + tests; splitting the two QA surfaces keeps agents in the 40–60k band. If agents near their budget, they checkpoint (commit + notes) instead of pushing through.
  • Two live-automation lessons already banked — the design oracle and the driver server replace manual window screenshots permanently, so the screenshot share should fall naturally in future epics.
