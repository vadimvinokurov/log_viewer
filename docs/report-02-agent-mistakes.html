The one meta-finding. Prose rules decay within a day; mechanisms stick. The agent-brief, the bd prime hook and live_check.mjs changed behavior permanently; five written rules (heredoc ban, agent caps, skill invocation) were each violated again within 24 hours. Every recommendation below is therefore stated as a mechanism — a hook, a script, or a spawn-prompt field — with the rule text only as a fallback.

Pattern catalog

P7 · Runaway agents — the largest single bucket agent

What: after the token rules landed (11-24 morning) agent sizes multiplied 5×: 628 k / 578 k / 385 k / 361 k / 327 k tokens vs the 44–85 k band of the previous day. One UI agent spent 21+ minutes monitoring its own background benchmark run, paying its full context every poll round. ≈2.65 M subagent tokens on 11-24 alone. Cause: no cap in the spawn prompt; waiting/monitoring parked inside a long-lived agent. Cost: the biggest billable bucket in the project.

exists rule 7 ("cap and checkpoint agents") — failed as prose. new (a) an explicit budget line in every spawn prompt ("≤ ~120k tokens / ≤ 60 tool calls; at the cap → checkpoint via bd update --notes and stop"); (b) monitoring background jobs is the coordinator's job, never a parked agent.

P1 · Token-budget blindness until the 429 kill agent

What: 16 usage-limit kills across three sessions; two agents died mid-task at <20 k partial spend; on 11-25 a weekly limit froze the session and the owner poked it six times «продолжи» before anything answered. Cause: checkpoints were taken at milestones, never before the most expensive steps (full gates, benchmarks) — exactly where a kill hurts most.

exists rule 7 (checkpoint agents). new checkpoint-before-long-gate: before any full workspace gate / benchmark / big e2e run, post a bd update --notes checkpoint and announce the expected duration. A stop with no resume note is a bug class of its own (see P8).

P5 · Debugging by shell-escaping into files agent

What: the driver.rs heredoc fight (5–6 failed python-heredoc rounds, "tens of thousands of tokens", Write tool solved it first try); the same pattern resurfaced even after rule 7 — a broken macOS sed -i and 14 consecutive heredoc edits of live_check.mjs on 11-24/25. Cause: habit; rule text alone failed twice.

exists rule 7 bullet + agent-brief trap. new a PostToolUse hook counting Bash-based file mutations (sed -i, heredoc redirects, perl -pi, tee file) and blocking the third with "use Edit/Write / rewrite the file". This is the cheapest mechanical win in the kit.

P2 · Late verification — CI catching what local gates missed agent

What: v0.2.0 (11-25 07:16): tag pushed, CI's tsc -b caught two type errors vitest cannot see (esbuild strips types) because the local gates ran with a stale tsbuildinfo cache and no fresh tsc -b. v0.1.0 had been re-tagged twice the night before (golden anti-aliasing nondeterminism; missing GTK libs on ubuntu). Cause: agent ran an approximate subset of the gates and treated green vitest as type coverage.

exists rule 9 + PIPELINE §6a. new scripts/release_gates.sh that runs the exact CI sequence (wiping tsbuildinfo first) as the only sanctioned path to a tag, plus a pre-push hook verifying the script's last green run is newer than the tag commit.

P4 · Debugging by narration instead of measurement agent

What: the e2e suite stalled; the first response was a confident explanation «это не виснет, а медленно работает». One timestamp check later: the suite took 14 seconds and state 33 blocked on a never-resolving downloadAndInstall promise. The e1/e3/e6 live-check plateau was narrated as "scroll behavior" for two rounds before the per-probe counts walk was proven the cause. Cause: theory before evidence.

exists superpowers:systematic-debugging. new hard clause: when a run exceeds its expected duration 2×, the first action is a timed observation (timestamps, progress markers) — no cost claim without the number. Extended "numbers instead of screenshots" to durations.

P6 · Agent prompt bloat — spec semantics paid 9+ times agent

What: early prompts restated spec sections inline and pointed at 4–6 "read-first" files; each agent re-decoded conventions independently (that duplication is also where the case-insensitive import bug class came from). Fix already delivered: docs/notes/agent-brief.md — prompts dropped ~1 k tokens → ~30 lines, and this is the best-verified saving on record.

exists rule 7 + agent-brief. new kit skill "shared-agent-brief": template (where truth lives / hard constraints / conventions / spawn contract / known traps) + the smell test "a spawn prompt longer than ~15 lines means missing context goes into the brief, not the prompt".

P8 · Dead air — silent stops and empty replies shared

What: after limit kills the session looked like a hang — «чет встал агент походу», «чет висло все»; two literal empty "no response" turns answered the owner's poke; the owner instructed «ты продолжай работу, не останавливайся» against an agent that had stopped early. Cause: stops without a user-visible status line. Note: this is also a coordinator behavior — every stop needs one line: done / waiting on X (id) / resumable at bead Y.

new kit rule: status-on-stop for every agent and the coordinator; a silent stop is reopened immediately. Cheap, high owner-trust value.

P3 · Trusting completion claims without artifacts shared

What: agents reported "all gates green" while the milestone live check failed in the real window three runs in a row (viewport anchoring, traced to the per-probe counts walk); the spec's "6.4M lines" figure lived in docs until the first benchmark measured 1,294,246. Cause: green tests treated as completion; verbal status accepted.

exists rules 4–5, bd acceptance = commands. new spawn template field: every done-claim carries gate outputs (command, counts, exit codes); a bare "all green" counts as not reporting.

P9 · Requirement churn around design taste owner

Recommended working mode with AI agents (going forward)

  1. Every spawn prompt contains five fixed fields: bead id + brief pointer; ≤3 files; exact gate commands; the token/call cap; the checkpoint + status reporting contract. Anything longer signals missing context — write it into the brief or the bead, not the next prompt.
  2. Done = outputs. Accept an agent's report only with gate outputs attached; run the one scoped gate yourself to spot-check before closing the bead.
  3. Design feedback in batches on the mock; app port starts only on explicit mock approval (one review round instead of 20 streaming corrections — the 1.5-hour churn session cost more than the whole release-pipeline day).
  4. Never let an agent wait on background work; monitoring is the coordinator's job or a foreground Monitor — an agent polling for 20 minutes pays its whole context per round for zero output.
  5. Watch for the 429 pattern: if a session or agent is entering a full gate or benchmark, it checkpoints first. After any silent stop, the coordinator posts a one-line resume status before anything else.
  6. Any repeated correction is a mechanism candidate. When the same correction appears the second time (heredoc, skill-trigger, green claims), stop writing rules and write the hook/script — this report's meta-finding.
