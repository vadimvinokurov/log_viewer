Функциональная спецификация v1.0 · 2026-11-22

Log Viewer

Документ описывает функциональность существующего приложения v2.0 — только то, что оно умеет и как ведёт себя с точки зрения пользователя. Архитектура, код, стек и внутренние структуры намеренно не описываются. Целевая аудитория — команда, которая будет переписывать приложение с нуля на новом стеке.

2024-01-01T10:00:00.000 app/main LOG_MSG Starting application

Эталонный файл: 842 МБ · 6.4 млн строк · 405 категорий

1.Общее описание

Log Viewer — настольное десктоп-приложение для просмотра больших текстовых файлов логов. Ключевые возможности: разбор строк на колонки, скрытие строк фильтрами и по категориям/уровням, цветная подсветка совпадений, поиск с навигацией, закрепление (pinning) важных строк, командная строка в стиле vim, горячие клавиши.

Платформы: macOS и Windows. Одиночное окно, без мультидокументности, без сетевых функций, без редактирования логов — только чтение.

Требование по объёму данных. Приложение должно «справляться» с файлом в сотни мегабайт. Эталон: 842 МБ / 6.4 млн строк / 405 категорий.

2.Открытие файла

Открытие файла — двумя способами:

  1. кнопка «Open» в нижней панели → диалог выбора файла;
  2. drag-and-drop файла на окно (берётся первый перетащенный файл).
  • Загрузка файла не блокирует UI: окно остаётся отзывчивым, результат применяется по завершении.
  • Каталог последнего открытого файла запоминается и используется как стартовый для диалога.
  • Несуществующий файл / ошибка чтения → сообщение об ошибке пользователю (сейчас выводится в статус-область; статус-область спроектирована в нижней панели, вывод в неё в v2.0 отключён), данные не теряются.
  • До загрузки файла таблица скрыта и показан пустой экран-заглушка с текстом «Drop a log file here or click Open».

2.1. Перезагрузка файла (Ctrl+R / кнопка «Reload»)

Файл перечитывается с диска. Поведение при перезагрузке:

СостояниеПоведение
Активные фильтры (текстовые)Сохраняются, пересчитываются заново
Включённость фильтров (on/off)Сохраняется
Подсветки (highlights)Полностью сохраняются
Отключённые уровниСохраняются
Отключённые категорииВосстанавливаются по имени (если категория ещё есть в файле)
Новые категории (появились после перезагрузки)Включаются, если все категории включены («All» включён); иначе выключаются
ПиныСбрасываются (все пины снимаются)
Активный поискСбрасывается, панель поиска закрывается

Загрузка нового файла ведёт себя так же, как перезагрузка.

3.Форматы логов и разбор строки

Автоматически определяются два формата (по первой непустой строке). Примеры обоих форматов для проверки разбора лежат в test_logs/:

Формат A — «ksiva»
timestamp category [LOG_LEVEL] message

Уровень — длинное имя LOG_LEVEL; пишется без скобок (LOG_MSG) или в скобках ([LOG_MSG]), в реальных файлах «ksiva» — без скобок. Уровень необязателен: если его нет, уровень строки — MSG. Категория может отсутствовать (тогда uncategorized).

Пример: 2024-01-01T10:00:00.000 app/main LOG_MSG Starting application

Формат B — «plain»
time elapsed level_short category message

Пять полей: первое — время суток HH:MM:SS.mmm (без даты), второе — elapsed (при разборе отбрасывается), далее уровень, категория и сообщение.

Пример: 10:00:00.000 0.123 msg cfg Application started

Правила разбора, одинаковые по смыслу для обоих форматов:

  • Разделитель — произвольные пробельные символы (в реальных файлах встречаются серии пробелов). Первое поле — timestamp.
  • Формат A: второй элемент — категория, третий — проверяется на уровень логирования.
  • Формат B: второе поле (elapsed) отбрасывается, третье поле — проверяется на уровень, четвёртое — категория.
  • Если проверяемый элемент распознан как уровень → остаток строки = сообщение.
  • Если элемент не распознан как уровень → уровень строки = MSG, а сам элемент и всё, что после него, считается сообщением. В реальных файлах Формата B уровень есть в каждой строке; в Формате A тег уровня пишется только для уровней кроме MSG.
  • Если у строки только одно поле (нет категории) → категория uncategorized.
  • Если у строки два поля (timestamp + текст) → категория uncategorized, уровень MSG, второе поле — сообщение.
  • Пустая строка → пустое сообщение, категория uncategorized, уровень MSG.
  • Timestamp отображается как время суток HH:MM:SS.mmm (если в timestamp есть дата через T, показывается только часть после T).
  • Категории иерархические: разделитель внутри имени — / (пример: app/main/db). Дерево категорий строится по этому разделителю.

3.1. Уровни логирования

Шесть уровней. В файле могут встречаться длинные имена (LOG_MSG, …) и короткие коды: crt (CRITICAL), err (ERROR), wrn (WARNING), msg, dbg (DEBUG), trc (TRACE).

DEBUGосновной цвет текста🟪

Весь текст строки окрашивается цветом уровня (не отдельная ячейка).

4.Главная таблица

Line50px
Time110px
Category150px
Message600px

Ширины по умолчанию; заголовки колонок видны.

  • «Line» — порядковый номер строки в исходном файле (1-based), сохраняется при скрытии строк. По нему работают fn, hn, pn.
  • Для длинных сообщений и широких колонок горизонтальная полоса прокрутки появляется только тогда, когда таблица по ширине не влезает в окно.
  • Горизонтальной прокрутки с тачпада нет вообще: жесты двумя пальцами и инерционные смахивания игнорируются (вертикальная прокрутка тачпадом работает как обычно).
  • По горизонтали прокручивать можно только мышью: наклоном колёсика — прокручивает только по горизонтали (не «уезжая» по вертикали) — и перетаскиванием самой полосы прокрутки.
  • Скролл к строке не должен сбивать горизонтальную позицию.
  • Прокрутка по пикселям (плавная), компактная высота строки (~высота глифа + 6px).
  • Встроенный в таблицу поиск по вводу с клавиатуры (type-ahead) отключён.
  • Мультивыбор строк (Ctrl/Shift-click), выбор всей строки.
  • Копирование: Copy (Ctrl+C или контекстное меню) кладёт в буфер сырые строки файла как есть (не отформатированные колонки), разделённые \n; Copy Message — только содержимое колонки Message.
  • Отображается только поднабор строк, прошедший все фильтры (см. §7); фильтрация не меняет нумерацию.
  • При изменении фильтров выделение сохраняется по номеру строки; вьюпорт сохраняет позицию относительно строки-якоря (таблица не «прыгает» при переключении фильтра).

Контекстное меню правой кнопкой по выделенным строкам:

  • Copy — всегда;
  • Copy Message — всегда;
  • Pin / Unpin — по наличию незакреплённых / закреплённых среди выделенных;
  • Highlight / Remove highlight — аналогично (для подсветки по номеру строки).

5.Режимы сопоставления (match modes)

Каждый текстовый критерий (фильтр, подсветка, пин) задаётся паттерном и одним из четырёх режимов:

РежимСуффикс командыСемантика
Plain(без суффикса)Поиск подстроки, case-insensitive
RegexrРегулярное выражение (Python-синтаксис), case-insensitive
Simple querysБулев язык запросов, case-insensitive (см. §6)
Line numbernТочный номер строки (1-based)
  • Некорректный regex → критерий не матчит ничего (без падения).
  • Все режимы case-insensitive.
  • Поиск (Ctrl+F, §8) поддерживает три режима — Plain, Regex и Simple query (тумблеры Regex и Simple в панели).

6.Язык простых запросов (Simple query)

Булевы выражения над подстроками:

  • Грамматика: OR < AND < NOT (приоритет NOT выше), скобки для группировки.
  • Термы — строки в двойных кавычках: "error".
  • Ключевые слова AND, OR, NOT регистронезависимы.

Примеры:

  • "error" AND "timeout"
  • NOT "info"
  • ("auth" OR "login") AND "failed"
  • Синтаксическая ошибка запроса (незакрытая кавычка/скобка, пустой терм, лишний символ) → критерий не матчит ничего; приложение не падает.
  • Семантика: для фильтров/поиска строка матчится, если выражение истинно на полном тексте строки; для подсветки подсвечиваются спаны всех вхождений каждого положительного терма (NOT-термы не подсвечиваются).

7.Фильтрация: совокупная семантика

Итоговая видимость строки определяется одновременным действием четырёх независимых механизмов:

  1. Текстовые фильтры (§5): строка видима, если она матчит хотя бы один активный фильтр (OR). Если фильтров нет → не сужают. Фильтр «по номеру строки» (fn) делает видимой конкретную строку.
  2. Уровни (см. §11): строка скрыта, если её уровень отключён.
  3. Категории (см. §10): строка скрыта, если её категория отключена.
  4. Пины (см. §12): строка, попавшая в активный пин, видима всегда — пин обходит и текстовые фильтры, и уровни, и категории.
видима = (текстовый_фильтр ИЛИ нет_фильтров) И уровень_включён И категория_включена ИЛИ пин

Счётчики по уровням в нижней панели (§11) считаются игнорируя переключатели уровней (показывают, сколько строк станет видно, если включить уровень).

8.Поиск

  • Поиск открывается горячей клавишей Ctrl+F — не командой из командной строки.
  • Панель поиска в стиле Google Chrome: компактная панель у верхнего края окна — поле ввода, компактные тумблеры режима, счётчик матчей, кнопки навигации и закрытия.
  • Кнопки панели:
    • Regex — тумблер: включён — паттерн ищется как регулярное выражение.
    • Simple — тумблер: включён — паттерн ищется как simple query (§6).
    • Оба выключены — поиск подстроки. Тумблеры взаимоисключающие: включение одного выключает другой. Все режимы case-insensitive.
  • Поиск работает только по видимым (отфильтрованным) строкам.
  • При старте точка отсчёта — текущая выделенная строка; находится первый матч от неё вниз. Таблица скроллится к матчу и выделяет его строку (по центру вьюпорта).
  • Счётчик матчей: «матч k из N»; при отсутствии матчей — «0 из 0».
  • ↑/↓ (и кнопки ↑/↓ в панели) — предыдущий/следующий матч, навигация зациклена по кругу. Строки, попавшие под поиск, переключаются стрелками, пока панель открыта.
  • Если панель закрыта, стрелки работают как обычная навигация по таблице.
  • Esc — закрыть панель поиска.

9.Подсветка (Highlights)

h plain hr regex hs simple hn N строка целиком
  • Подсветка не скрывает и не уводит строки — только раскрашивает.
  • При добавлении подсветке автоматически назначается цвет из палитры 10 цветов (по кругу):
gold orange coral lavender sky blue mint teal green sunny pink
  • Отрисовка: полупрозрачный прямоугольник цвета подсветки за текстом совпадения (символьные спаны), только в колонке Message. Для подсветки по номеру строки подсвечивается всё сообщение строки.
  • Активных подсветок может быть несколько одновременно; совпадения разных правил накладываются.
  • Каждая подсветка имеет чекбокс вкл/выкл (отключённая не отрисовывается) и удаляется по кнопке; смена цвета — по клику на цветную точку (системный диалог выбора цвета).
  • rmh — удаляет все подсветки.
  • Подсветки сохраняются при перезагрузке файла (§2.1).

10.Категории

  • Категории извлекаются автоматически при разборе; иерархия строится по /.
  • Боковая панель, вкладка «Categories»: дерево чекбоксов, без счётчиков строк (счётчики убраны 2026-11-25 ради перфоманса).
  • Верх «All»: чекбокс, управляющий всеми категориями сразу; категории — дочерние ноды All, её стрелка сворачивает/разворачивает верхний уровень, как у любой ноды (2026-11-25).
  • Чекбоксы трёх состояний: parent показывается «частично», если часть детей включена.
  • Снятие/установка флага распространяется вниз на всех детей и вверх на родителей.
  • Отключение категории скрывает все её строки (и строки детей).
  • Поиск по дереву: текстовое поле фильтрует видимость нод (нода видима, если совпадает сама или любой потомок); при активном поиске дерево раскрывается целиком.
  • Кнопка toggle схлопывания: развернуть всё / свернуть всё — свёртывание закрывает всё дерево целиком, у корня остаётся только строка All (2026-11-25).
  • Состояние раскрытости нод сохраняется при перестройке дерева.
  • Отключённые категории переживают перезагрузку файла (по имени; §2.1).

10.1. Прочие списки боковой панели

Вкладки: Categories | Filters | Highlights | Pinned (панель с вкладками, сворачивается по Ctrl+B, ширину можно тянуть прижатым к ней сплиттером).

  • Filters: для каждого фильтра — чекбокс, текст команды (:f pattern / :fr / :fs / :fn), кнопка удаления ✕; выключенный элемент визуально приглушён.
  • Highlights: то же + цветная точка (клик → выбор цвета) вместо префикса.
  • Pinned: аналогично фильтрам.
  • Текст элемента отображается с обрезкой по ширине, полный текст — в тултипе.

11.Уровни (нижняя панель)

⛔ CRITICAL 1240 🛑 ERROR 863 ⚠️ WARNING 12 044 ℹ️ MSG 5.8M 🟪 DEBUG 421k 🟩 TRACE 96k

Числа на кнопках — иллюстрация счётчиков, не реальные данные.

  • Ряд из шести кнопок-уровней (§3.1) в правой части нижней панели.
  • Кнопка показывает иконку уровня и счёт: сколько строк этого уровня будет видимо при текущих фильтрах и категориях (если сам уровень включён — совпадает с фактической видимостью). Счёт 0 → кнопка пустая по счёту.
  • Клик по кнопке — выключить/включить уровень (hidden/show). Активный уровень отображается цветом, неактивный — приглушённо.
  • Отключённые уровни сохраняются при перезагрузке файла (§2.1).

11.1. Нижняя панель, слева

  • Кнопки Open и Reload.
  • Командная строка (§13): плейсхолдер :type command...; активация по нажатию : вне поля ввода (поле получает фокус с текстом : и курсором после него).

12.Пины (Pinned lines)

  • Пин — правило сопоставления (те же 4 режима: p/pr/ps/pn N), а не список строк: :pn 5 — пин на строку 5; :p cfg — пин на все строки, содержащие cfg.
  • Закреплённые строки всегда видимы, обгоняя фильтры/уровни/категории (§7).
  • Пины отображаются во вкладке «Pinned»: чекбокс (вкл/выкл действия пина), текст, кнопка удаления.
  • rmp — снять все пины. Удаление по одному — из панели или через контекстное меню таблицы (Unpin).
  • При перезагрузке файла пины сбрасываются полностью (§2.1).

13.Командная строка

Плоская строка ввода в нижней панели. Синтаксис: :имя [текст]; начальное : можно опускать в поле ввода (всё, что отправлено из поля, трактуется как команда; если текст не начинается с : — игнорируется). Enter — выполнить, Esc — очистить и вернуть фокус таблице.

13.1. Реестр команд

КомандаАргументДействие
f, fr, fsпаттернДобавить фильтр
fnномерДобавить фильтр по номеру строки
rmf—Удалить все фильтры
h, hr, hsпаттернДобавить подсветку
hnномерПодсветить строку целиком
rmh—Удалить все подсветки
p, pr, psпаттернДобавить пин
pnномерДобавить пин на строку
rmp—Снять все пины

Правила валидации:

  • Неизвестное имя команды → ошибка «Unknown command».
  • Командам, требующим аргумент, пустой аргумент → ошибка.
  • fn/hn/pn требуют целое число от 1 до кол-ва строк; иначе — «Error: … out of range (1..N)».
  • rmf / rmh / rmp — аргументов не принимают и имеют ровно одну функцию: очистить все фильтры / все подсветки / все пины сразу. Других функций (удаление одного элемента, удаление по тексту) у них нет — удаление по одному только через панели или контекстное меню.
  • Сообщение об ошибке показывается пользователю (сейчас выводится в статус-область нижней панели; вывод в неё в v2.0 отключён); команда не выполняется частично.

13.2. История команд

  • Все введённые команды пишутся в персистентную историю (~/.logviewer/history.json).
  • ↑/↓ в поле ввода — навигация по истории: вверх — к более старым, вниз — к более новым; после последней возвращается пустая строка.
  • Подряд идущие дубликаты не добавляются; пустые команды не добавляются.
  • Максимальный размер истории — настройка history_size (по умолчанию 100).

15.Настройки и хранение

Все пользовательские данные лежат в ~/.logviewer/:

ФайлСодержимое
settings.jsonНастройки: history_size (int, 100), last_open_dir (str), default_categories_enabled (bool, зарезервировано)

  • Файлы создаются автоматически при первом запуске, если их нет.

  • Каталоги создаются лениво, ошибки диска не роняют приложение.

16.Требование к производительности

Единственное требование к производительности: архитектура с максимальной производительностью при работе с логом. Конкретные числовые бюджеты операций в спецификации не фиксируются — каждое действие (загрузка, фильтрация, категории, пины, подсветки, поиск, скролл) должно ощущаться мгновенным на файлах в сотни мегабайт.
