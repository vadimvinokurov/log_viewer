Architecture Summary

Data is stored in Structure-of-Arrays (SoA) layout on top of a single bytearray buffer. String fields (messages, timestamps) are not decoded until accessed — stored as (offset, length) spans into the buffer. Filtering uses vectorized numpy operations.

StageMechanismStatus
Line scanning numpy np.where on uint8 view SIMD-fast
Parsing Python for loop, per-line byte ops Bottleneck
Category tree np.unique + dict tree Fast
Level counting np.bincount Fast
Filtering numpy boolean masks + np.isin Vectorized
Message access Lazy decode from byte buffer Zero-copy

Bottleneck: _parse_plain_batch

parser.py:604-698 — 6,375,495 iterations of pure Python, ~3.7 µs/line.

Recommendations

Priority 1 — Parsing speed (5-20x gain)

Cython / C extension for _parse_plain_batch
Replace the Python loop with C code accessing char* directly. Eliminates Python interpreter overhead per line. Standard approach for parsers at this scale.
Expected: ~1-3s instead of 23s
Multiprocessing (chunk-based parallelism)
Split buffer into ~500K line chunks, parse in parallel processes, merge cat_name_to_id at the end. The codebase already has this pattern in parse_lines_batch but parse_batch_fast doesn't use it.
Expected: ~3s with 8 cores
Vectorized field extraction with numpy
For plain format, field positions are nearly fixed. Use numpy to find delimiter positions in bulk, then extract all fields at once without a Python loop.
Expected: 5-20x depending on field regularity

Priority 2 — Memory (-200 MB)

Drop timestamp_spans array
Timestamps are always field 1 — positions can be computed from line_starts on access. Remove 73 MB array.
-73 MB
Use uint32 for line_starts
Files under 4 GB don't need uint64 offsets. Switch to np.uint32.
-24 MB

Priority 3 — UX

Progressive loading
Display first 10K lines immediately (~0.1s), parse the rest in background. User starts reading before parsing finishes.
Perceived: 0.1s to first paint
Memory-mapped file (mmap)
Replace read_bytes() + bytearray with mmap.mmap(). OS manages paging, avoids double-buffering during read, reduces RSS.
Lower RSS, faster cold start
